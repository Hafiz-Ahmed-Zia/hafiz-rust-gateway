## Maintainer expectations

- Keep the issue tracker, roadmap, compatibility status, and release notes truthful.
- Review changes against the PRD, requirement IDs, accepted ADRs, and security contracts.
- Use private vulnerability reporting for suspected security issues.
- Require passing CI and a documented self-review while the project has one maintainer.
- Activate independent required approval after a second trusted maintainer joins.
- Never claim adoption, performance, compatibility, or enterprise readiness without named evidence.

## Adding or removing maintainers

Maintainer changes require a public governance pull request describing scope, permissions, security
responsibilities, and continuity impact. Repository access can be removed immediately for a
credible security risk, followed by a public explanation when disclosure is safe.
